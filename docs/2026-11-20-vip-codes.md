# Redeem codes (2026-11-20)

Design: `docs/superpowers/specs/2026-11-20-vip-codes-design.md`. Plan: `docs/superpowers/plans/2026-11-20-vip-codes.md`.
FlyffWeb only: no World or Database server change, no convert, no outer-repo change.

## What was built

**The panel (VIP tab → Codes):**
- **Make a code:** a name, VIP (none or 1-4) and days, up to 6 items (searched like the Gift box; counts up to each
  item's stack size), who can use it, and an end date and time in your own time zone (at most a year ahead).
  - **Everyone:** one code, once per account, with an optional "most uses" cap. You can type your own word
    (`LAUNCH2026`) or leave it blank for a random `XXXX-XXXX-XXXX-XXXX`.
  - **Only these accounts:** one code for the accounts you list. Each one is checked to exist.
  - **One-use codes:** 1 to 500 random codes, each usable once. Copy them or download them as a .txt file.
- **The list:** each code's state (On, Off, Expired, Used up), what it gives, its uses and its end time.
  - Turn a code off or on, and change its name or end time. What a code gives never changes.
  - **Codes** shows a batch's codes and who used each one. **Uses** shows each use: account, character, VIP given,
    any lower VIP it replaced, and whether the items were mailed.
- Every change goes in the Log tab. The codes themselves are never logged.
- **Bound (can't trade)** (owner, 2026-11-20, branch `vip-codes-bound`): a tick on each new code. The code's items
  are mailed with the game's own binds flag (`CItemElem::binds`, 0x02), so the World server refuses to let them be
  traded, dropped, mailed on, sold in a private shop or put in the guild bank. They can still be used, sold to an NPC
  and kept in the player's own bank. The panel list shows "(bound)", and the game window says "Bound to your
  character: these items can't be traded." Without the tick, items are normal, as before. A code made before this
  update stays unbound.

**The game (Start → Extras → Redeem Code; desktop and phone):**
- The player types or pastes a code. **Paste** reads the clipboard; where the browser gives none, the window says
  "Long-press the box and choose Paste." **Check** shows what the code gives, with item icons, and the bag slots it
  needs against the ones the player has.
- **Redeem** first checks the bag again. If the code would end a lower VIP, it warns and asks again ("Yes, redeem").
- When it is done, the window says the items arrive in the bag within about a minute. For VIP it says to log out and
  in again.
- The items come as in-game mail titled `Code reward #<n>`. The game moves them into the bag by itself. If the bag is
  full by then, the chat says they wait in the mailbox (Post, 15 days).
- Every refusal has its own line: wrong format, no such code, too many tries, expired, turned off, fully claimed,
  already used, not for your account, a higher VIP (with both dates), character not found, codes off, can't reach,
  something went wrong.
- If the website login ran out (after 12 hours, or a website restart), the window asks for the password and carries
  on with the same code. While in the world, the game keeps that login alive every 30 minutes.

**Safety:**
- One use per account per code.
- 10 wrong codes an hour per account and 30 per internet address; 30 Redeem presses an hour per account (refused ones
  count too).
- Two players redeeming the last use at the same moment cannot both get it: the database locks the code's rows.
- A redeem answer lost on the way: pressing Redeem again, or Check of the same code, gets the first answer back,
  never "already used".
- The website's public login can use codes but cannot write mail. The website answers first, then the panel's login
  writes the mails at once; if that fails, the 5-minute VIP job retries.
- The done lines also go in the chat, so closing the window while it works loses nothing.
- Code mails that arrive while the player is logging out and in are still moved into the bag: the game asks the
  mailbox when the mail notice is on at entry, and again for 3 minutes.
- Dates are shown in the player's own time zone.
- Log lines: `code <address> <account> <code id> <result>`. Never the code itself.

## Rulings (calls made while building)

- A lower-tier code is refused whole, items included, while a higher VIP runs (owner's pick). A higher-tier code needs
  the player's confirm, then the lower VIP ends now. The panel's Uses list keeps what it replaced.
- Codes are stored as typed (capitals, no dashes), not hashed, so the panel can show and copy them later.
- Redeem stays pressable when the bag is short. Each press reads the bag again and says how much room is needed, so a
  player can make room without checking again.
- On a phone, the window keeps its desktop layout (it fits above the task bar) with bigger buttons. It is not
  re-flowed into a compact panel like Teleport's.
- Codes need both the `vip` and `admin` sections of web.config.json. Without them, the window says "Codes are not
  available right now."

## On the VPS

There is nothing new to set up: `Update-FlyffWeb` makes the new tables (`Install-Vip.ps1` runs by itself while the
panel is on).

1. Make the FlyffWeb package as usual (code only, no convert, no gear sync).
2. Copy it to the VPS, then run:
   ```
   run.bat Update-FlyffWeb -From <the new FlyffWeb folder>
   ```
   It stops and starts the gateway and the web service, so pick a quiet minute.
3. Panel → VIP tab → Codes: make a test code, then try it in the game.

### In the VM (with the servers, never on the live server)

1. Make an Everyone code: VIP 1 for 3 days plus 5 Remantis Laccotte. In the game, Check shows them. Redeem says Done.
   Within about a minute the potions are in the bag. After a relog, the VIP star shows.
2. The same code again on the same account: "You already used this code."
3. A batch of 2 one-use codes: one works on account A; the same code on account B says "This code was already used."
4. An Only-these code for account A: account B gets "This code isn't for your account."
5. Give account A VIP 4. A VIP 1 code is refused with both dates, and nothing arrives.
6. Account A with VIP 1: a VIP 3 code asks "Yes, redeem". After it, VIP 3 runs and the panel's Uses shows VIP 1 replaced.
7. A bag with no empty slot: Check shows the shortfall in red, and Redeem says to make room.
8. Fill the bag right after Redeem: the chat says the items wait in the mailbox, and Post has them.
9. Turn a code off in the panel: "This code is no longer active."
10. Restart the web service while in the game, then Check: the window asks for the password, then shows the offer.
11. Redeem a VIP + items code, log out at once, wait 70 seconds at character select, then enter: the items land in
    the bag by themselves, and the VIP star shows.
12. A code with **Bound** ticked: its items arrive. Trading one to another player, dropping it, or putting it in a
    private shop is refused. The same items from a code without the tick trade normally.
