# Auto Play (farm bot, auto pots, auto skill) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A custom, owner-approved Auto Play for FlyffWeb: auto pots, a farm bot and auto skills/buffs, on desktop
and phone.

**Architecture:** Pure rule files in `apps/client/src/world/autoplay/` (unit-tested), one `AutoPlay` controller stepped
from `WorldScreen.step`, which drives the existing V15 paths (attack loop, skill use, item use, pickup) through a narrow
hooks object. UI in `apps/client/src/world/hud/autoPlay/`.

**Tech Stack:** TypeScript, vitest, Playwright (owner only), the FlyffWeb HUD (`WindowFrame`).

**Spec:** `docs/superpowers/specs/2026-11-15-auto-play-design.md`. Research:
`docs/superpowers/2026-11-15-farm-bot-research.md`.

**Milestones and sizes**

| M | What the owner can test at the end | Size |
|---|---|---|
| M1 | Auto pots, desktop: Start menu "Auto Play", Potions tab | Medium (5 tasks) |
| M2 | Farm bot, desktop: Farm tab, AUTO button, stop rules, loot | Large (6 tasks) |
| M3 | Auto skill and buffs: Skills tab | Medium (3 tasks) |
| M4 | Phone and AFK: phone layouts, menu 10+9, Wake Lock, battery saver | Medium (4 tasks) |
| M5 | Owner's e2e spec and checkpoint | Small (1 task) |

Each milestone ends with a checkpoint doc `docs/2026-11-xx-auto-play-mN-checkpoint.md` for the owner (commands, what
pass looks like). No server change in any milestone.

## Global Constraints

- **Custom feature** (owner, 2026-11-15). Mark new code with a comment `custom (owner 2026-11-15): Auto Play`; cite the
  V15 source where V15 behaviour is reused.
- With Auto Play off (the default for a new character), nothing changes for the player.
- No new packet types. The bot only calls: `AttackLoop.onMoverPressed(id, now, true)`, `attackButtonDown/Up(now)`,
  `SkillUse.useActionSlot()`, `SkillUse.useSlot(skillIndex)`, `ItemUse.use(objectId, 'bar')`, `ItemActions.pick(id, now)`,
  `OwnMover.walkTo(own, pos)`.
- At most one new attack/skill/walk/pickup command per rules step; potions: one per row per 500 ms, then wait for the
  gauge to change or 800 ms.
- Values (from the spec): radius default 15 m, 5-30 m, step 5; pots HP 50 / MP 30 / FP 30 %, 10-90 %, step 5; stuck 10 s
  → skip 60 s; 3 stuck in a row → return to anchor; no target → check every 500 ms, return if > 3 m from the anchor;
  leash radius + 5 m; loot items that appear within 5 m of our kill in the 3 s after it, give up after 6 s; buff recast
  under 10 s left; ready skills max 4; buffs max 8; low-HP stop below 20 % with no HP item; skill refused → wait 3 s;
  chain end/fail → wait 1 s; another player's hit counts for 10 s; stop-after 1-12 h (0 = off); phone battery saver
  after 2 min with no touch.
- Ranks never chosen (unless they hit us): 4 RANK_BOSS, 5 RANK_MIDBOSS, 7 RANK_SUPER.
- Farm blocked worlds: 208, 202, 211, 241-244, 121-125, 151-167, plus every world in `Resource/PartyDungeon.lua`; and
  during a duel. Pots blocked: 208, 202, 241-244; and during a duel.
- Settings key `flyffweb.autoPlay.<playerId>`, every localStorage call in try/catch.
- Texts (exact): "Auto Play", "Auto Play started.", "Auto Play stopped: <reason>.", "Auto pots: no <HP|MP|FP> items
  left.", phone tip "Keep the game open and the screen on. Locking the phone stops Auto Play." Reasons: "you died",
  "low HP, no potions", "attacked by <name>", "message from <name>", "duel", "left the area", "not allowed here",
  "you took control", "flying", "time limit".
- Phone CSS only in `@media (max-width: 1000px) and (pointer: coarse)` blocks.
- Builders run quick checks only: `npx vitest run apps/client`, `npm run typecheck`, `npm run check:public-build`, and at
  most one run of an e2e spec they touched. Full e2e goes to the owner. Commit on the build branch; never push.

## Review Focus

1. A monster we are fighting walks out of the radius → keep fighting it until it dies (test in Task 7).
2. The HP potion stack runs out and another stack of the same item (new object id) is in the bag → keep using it
   (test in Task 3).
3. In a party, a party member's monster and our party's drops are not "someone else's" (tests in Tasks 6 and 8).
4. Saved settings name a skill or item the character no longer has → skipped and shown greyed, no throw (tests in
   Tasks 1 and 12).
5. Desktop tab hidden: `stopOwnMover` clears the walk, the bot re-issues it next step (test in Task 9).
