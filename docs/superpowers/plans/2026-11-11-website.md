# FlyffWeb Website Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** FlyffWeb serves a home page at `/`, account creation at `/sign-up` and the game at `/play`, with a small
`apps/web` service that creates accounts and reports the server status, and a gateway allow-list that closes the
certifier's SQL hole.

**Architecture:** `apps/client` becomes a Vite multi-page build: the game's page moves to `play/index.html` unchanged,
and home and sign-up are small pages under `src/site/` that never import the game. A new Node service, `apps/web`,
listens on 127.0.0.1:8091 behind Caddy's `/api/*`. It checks the sign-up rules shared with the page
(`packages/protocol/src/web/signUp.ts`) and calls `usp_CreateNewAccount` through `mssql`. The gateway's relay refuses any
certifier packet outside a four-type allow-list or with a bad account or password.

**Tech Stack:** TypeScript (ESM), Vite multi-page, Node `http`/`crypto`/`net`, `mssql`, vitest, Playwright (Chromium),
Caddy (hosting guide).

**Spec:** `docs/superpowers/specs/2026-11-11-website-design.md`

  - **Password:** 8–31 printable ASCII characters (0x20–0x7e), with at least one letter and one digit, and not equal to

  - **Email:** empty, or `x@y.z`-shaped and at most 100 characters.

  - `Enter an account name.`
  - `The account name must be 4 to 32 characters long.`
  - `Use only letters, numbers, - and _ in the account name.`
  - `That account name is reserved.`
  - `The password must be 8 to 31 characters long.`
  - `Use only letters, numbers, spaces and common symbols in the password.`
  - `The password needs at least one letter and one number.`
  - `The password cannot be the account name.`
  - `The passwords do not match.`
  - `Enter a valid email address, or leave it empty.`
- **Ruling** (plan vs spec §3.6): the gateway runs from source with `tsx` (`npm run gateway`), so `apps/web` does too

## Review Focus

1. **A sign-up sent twice** (a double tap, or a slow network and a second press) must create one account and show
   success, not "name taken". Tested in Task 5: the button is disabled while a request is in flight.
2. **A player who takes longer than 30 minutes** gets a `ticket` answer. The page must fetch a new ticket, keep the
   fields and ask them to press again, never leave them stuck. Tested in Task 5.
3. **Home and sign-up on a portrait phone** must show their content, not the "turn your phone" cover, which belongs to
   `/play` only. Tested in Task 4 with a portrait viewport.
4. **A slow or hanging database** must not hang `/api/status` or the home page. The count times out after 2 s and
   answers `players: null`. Tested in Task 10.
5. **An account typed with capitals or surrounding spaces** is stored trimmed and lower-cased, and the hand-off fills
   the login with that same form. Tested in Tasks 1 and 5.

  ```ts
  export type SignUpField = 'account' | 'password' | 'confirm' | 'email';
  export interface SignUpForm { account: string; password: string; confirm?: string; email: string }
  export interface SignUpProblem { field: SignUpField; message: string }
  ```

  `confirm` is checked only when present (the server has none). The checks run in this order: account (empty, length,
  characters, reserved), password (length, characters, letter-and-digit, equal to name), confirm, email. The first
  failure is returned.

- Produces:

    'server' | 'forbidden' | 'unreachable'; field?: SignUpField }`.
  - `class SignUpApi { constructor(fetchFn: typeof fetch); ticket(): Promise<string | undefined>; send(form: { account:
    string; password: string; email: string; website: string; ticket: string }): Promise<SignUpAnswer> }`. It POSTs JSON
    to `/api/sign-up` and maps the HTTP status and body `{ error, field }`. A network failure is `unreachable`.
  - `putSignUpAccount(storage: Storage | null, account: string): void` and `takeSignUpAccount(storage: Storage | null):
    string` (it reads, then removes, `flyffweb.signUpAccount`; a missing storage or a thrown access gives `''`).

**The page:**
- **Fields:**
  - Account (`autocapitalize=none`);
  - Password and Confirm password (`autocomplete=new-password`);
  - Email (optional);
  - a `website` text input in a container with the `trap` class: off screen, `aria-hidden="true"`, `tabindex="-1"`,
    `autocomplete="off"`.
  - Under the password: `Use a password you don't use anywhere else.`
- **On load:** fetch a ticket.
- **On submit:**
  1. Run `checkSignUp` with the confirm field; a problem shows its message by its field, focused.
  2. Otherwise disable the button, send, and enable it again when the answer comes.
- **Answers and their messages:**
  - `ok`: hide the form and show `Account created.` with a **Play now** link (`/play/`), after
    `putSignUpAccount(sessionStorage, normalizeAccount(account))`.
  - `taken`: `That account name is taken.`
  - `invalid`: the field's own message, from re-running `checkSignUp`.
  - `too_many`: `Too many sign-ups from your network. Try again later.`
  - `paused`: `Sign-ups are paused for a few minutes. Try again soon.`
  - `ticket`: fetch a new ticket and show `Please press Sign up again.` (the fields stay).
  - `server`, `forbidden` and `unreachable`: `Something went wrong. Please try again later.`
- **After an error:** the passwords are cleared, the other fields kept.

  ```ts

  export interface HttpAnswer { status: number; body: Record<string, unknown> }
  export interface SignUpRequest { address: string; origin: string | undefined; contentType: string | undefined; body: Buffer }
  export interface SignUpDeps { config: WebConfig; store: AccountStore; tickets: TicketBook; attempts: HourlyLimit;
  ```

  - **Order and answers** (spec §3.4 steps 1–7):
    - `415 {error:'type'}` unless the content type starts with `application/json`;
    - `413 {error:'size'}` over 1024 bytes;
    - `403 {error:'forbidden'}` unless `origin === config.siteOrigin`;
    - `400 {error:'invalid'}` for JSON that does not parse or is not an object;
    - `429 {error:'too_many'}` past the attempt limit (`attempts.add` comes first, then `allows`);
    - `400 {error:'ticket'}` unless `tickets.check(...) === 'ok'`;
    - a non-empty `website` gets `201 {ok:true}` with nothing created;
    - `400 {error:'invalid', field}` from `checkSignUp(..., config.reservedNames)`;

    - then `store.create(normalizeAccount(account), hashPassword(password), email)`: `1` gives `201 {ok:true}` and adds
      to both creation limits; `0` gives `409 {error:'taken'}`; anything else, or a throw, gives `500 {error:'server'}`.
  - **Fields:** only `account`, `password`, `email`, `website` and `ticket` are read; strings only (a non-string is
    `invalid`). `email` defaults to `''`.
